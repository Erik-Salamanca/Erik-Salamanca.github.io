Mechatronics Robot Design

In MAE 3780 Mechatronics our final project was to create a robot that would compete against our classmates in a cube collecting competition.

Role
Lead Designer
Duration
1 months
Tools
Fusion 360, Ardunio Code
Status
Completed
Overview

The competition was to collect as many of the 20 randomly scattered cubes as possible. These cubes would start in the middlish on either side of the blue and yellow color border. To count as acquired the cube had to be fully inside of the robot perimeter. The Starting configuration was a 8 inch square and the robot could extend out into a 12 inch cylinder after the match had started. An image of the field can be seen below in Figure 1.

For the competition we were given a frame, continous servo motors, H-bridges, rotational servo motor, color sensor, and two QTI sensors. We were also given a $40 budget that we could send on additional lab equipment or at specific online venders. In addition, we were able to use any equipment in our lab kits given to use at the begining of the semester. This included wires, resistors, capacitors, buttons, switches, and 1 Arduino Uno.

Fig. 1 — Here is the field we would be competing on. Our robot would start on either the yellow or blue side (randomly decided at the start of each match) and have to collect the cubes in the middle of field.
Contributions

Our robots strategy was drive at an angle until we reached the color border between blue and yellow. The robot would then turn right until it was parallel with the color border where it would then drive stright along the border. It would have a funnel in the front to acquire cubes it ran into along the border until it reached the right black border. There it would simiply start driving around randomly staying with in the black border trying to acquire any cube that got knocked around by chance. It would do this until the match ended.

My major contribution to this project was making all the parts and getting them ordered and manufactored using CAD. I would model all the parts that were needed and making drawinging of them to be laser cut or STL files to be 3D printed. I would then sumbit the orders to RPL lab so they would have the files and I would be able to get them laser cut or printed when I went to open hours. Seen in Figure 2 is a 3D rendering of the robot based on the CAD model.

Fig. 1 — This is a rendering of the CAD work I did for the robot. Not depicted is the breadboard used to wire the electronics and the two batteries used to power the ardiuno and motors.

I also helped with writing the assembly of the robot and coding the major functions. For the code we were restricted to using arduino registers only (no arduino libraries except for a few functions). My major contributes to the code where the intial writing on the drive functions, which later where modified as different arduino pins where used, and helping debug code after it was written. This inclued looking a code that wasn't working properly with fresh eyes to try to catch errors that the intial teammember missed. I have inclued a PDF file of the code that was used at the end of this page. Each section of the script is commented with its purpose.

The wiring of the robot was mainly done by another teammember, but I did help and have a good understanding of the the worbot is wired. I have made a circuit diagram of the robots wiring, which can be seen in Figure 3 below.

Fig. 1 — This is the electrical diagram of the robot. The L9110 are H-bridges which are externally wired by us connect to 2 motors. There are also 2 QTI sensor for detecting the black border which use external 10K Ohm resistors. The color sensor is the last component and is used for detecting the color difference between yellow and blue.
Performance

Our robot ran into some issues on competiton day. One issue was that although we could acquire a good amount of cubes at the start holding onto them was more difficult. As the robot turned it would lose cubes it had acquired. Additionally the board had a lip just beyond the black border. The board we had practiced on did not have this lip and it resulted in us getting stuck about halfway through every match. We would also loose cubes to this edge as they would fall off the border and not be in our robot anymore.

We did still win some matches, but many of them we would be winning then lose the cubes we had driving around and get stuck on the edge of the board. Some changes I would make to our robot if I could redesign it now we would be:

  • Change one: Make the robot stop and backup at the black border to avoid falling off.
  • Change two: Have front of funnel close as to not lose cubes when backing up or turning.
  • Change three: Have the robot stop after reaching the edge of the board a certain number of times (maybe only 2-3).

I think just these three changes would have really improved our robot and the number of matches we would be able to win.
